# 飞牛播放记录同步插件

在两台飞牛影视之间同步**相同影片**的播放进度和已看完标记。两边各自独有的影片不受影响。

## 能做什么

- 双向同步：A 看到 30 分钟，B 打开同一部片从 30 分钟续播；反过来也一样
- 同步「已看完」标记，两边的观看状态保持一致
- 只同步两边都存在的影片，自动跳过各自独有的
- 支持电影和电视剧分集，分集按「剧名 + 季号 + 集号」对应
- 定时同步：日常增量检查（默认 15 分钟） + 低频全量扫描（默认 6 小时），也能手动立即执行

## 影片怎么配对

按优先级用三种标识，任一命中且唯一即配对：

1. IMDb 标识
2. TMDB 标识
3. 标题 + 年份（标题会去掉季数后缀，让「庆余年 第二季」和「庆余年」能配上）

电视剧分集额外叠加季号和集号。如果一部片匹配到多个候选，直接跳过，不会乱配。

## 冲突怎么处理

两台都改动了同一部片时，按配置里的策略处理：

- **保留冲突（默认）**：谁都不覆盖，等下次；状态一直不一致就一直保留
- 进度大的优先
- 以 A 为准 / 以 B 为准

首次遇到一部片且两端状态不一致时，按上面的冲突策略拉齐一次（默认「保留冲突」则不动手，等你自己定夺）。之后只有相对基线发生变化的那一端才会被推送到另一端。

## 两种运行方式

只有一个定时任务，每轮先看全量是否到期，没到期就走增量。

| 方式 | 频率 | 读什么 | 一轮开销（实测） |
|---|---|---|---|
| 增量检查 | 默认 15 分钟 | 只读两端「继续观看」列表 | 2 个请求，约 40 KB，0.5 秒 |
| 全量扫描 | 默认 6 小时 | 整个媒体库，按需展开目录树 | 5～41 个请求，2～3 MB |
| 深度扫描 | 默认 24 小时 | 全量 + 完整展开所有剧集树 | 41 个请求，约 1.4 秒 |

增量检查靠上一轮记下的条目对应关系直接定位对端，适合追正在看的进度。「已看完」标记不会出现在继续观看列表里，所以由全量扫描兜底；一旦发现有尚未配对的新片，当轮会自动改跑全量。

全量扫描不是每轮都把整棵树重拉一遍：两端整剧都已看完的直接跳过；顶层状态没变化、上一轮又已经完整比对过的剧集树也跳过。这样稳态下全量只要 5 个请求（原来 89 个）。为了兜住分集层的手动改动，每 24 小时强制完整展开一次，这就是深度扫描。

## 配置

| 配置项 | 说明 |
|---|---|
| 启用插件 | 打开后定时服务才会注册 |
| 立即运行一次 | 勾选并保存后马上同步一次，之后自动关闭该开关，恢复按间隔运行 |
| NAS A / B 地址 | 形如 `https://192.168.1.10:5666`，不用加 `/v`，插件自动补 |
| NAS A / B 用户名、密码 | 插件内单独填写，两台可以不同账号 |
| 访问码 | 飞牛开了访问码才填，没开留空 |
| 同步方向 | 双向 / 仅 A→B / 仅 B→A |
| 两边都改动时 | 冲突策略，见上 |
| 同步已看完标记 | 关闭后只同步播放位置 |
| 增量检查间隔 | 分钟，最小 5；只读继续观看列表，开销极小 |
| 全量扫描间隔 | 小时，最小 1；补「已看完」标记与新片配对 |
| 重置同步基线 | 勾选并保存后清空历史比对记录，下一轮按首次配对重新拉齐；用完自动关闭 |
| 重新信任证书 | NAS 换了 HTTPS 证书导致指纹不一致、同步被拦时勾一次；用完自动关闭 |
| 同步完成后通知 | 有实际写入或失败时才发消息，没有变化不打扰 |

## 使用

1. 填好两台 NAS 的信息
2. 勾选「立即运行一次」并保存，插件会在几秒后同步一次，日志里看匹配了多少部
3. 一次性任务执行后开关自动关闭，之后按「同步间隔」定时运行
4. 插件详情页可看最近一次结果和变更明细

也可以用命令 `/fnvsync` 手动触发，或到「设定 → 服务」手动运行。

接口：

| 接口 | 作用 |
|---|---|
| `POST plugin/FnVsync/run` | 走增量，出现新片会自动转全量 |
| `POST plugin/FnVsync/syncall` | 强制全量 |
| `POST plugin/FnVsync/dryrun` | 试运行：完整比对但一条都不写，返回将要同步的清单 |
| `GET plugin/FnVsync/export` | 导出配置与基线（不含密码），换机时用 |
| `POST plugin/FnVsync/import` | 导入上一步的导出内容，省掉重新全量配对 |

每次运行在日志里打一行中文摘要，例如：

```
飞牛同步完成（增量核对）：配对 17 部，同步 0 条，用时 2.1 秒，共 2 次请求
```

有写入或异常时才会多出「跳过 / 冲突 / 失败」几项。更细的开销（流量、网络等待、重新登录次数、令牌复用、分集展开次数、写完抽样回读结果）放在调试级日志里，平时不刷屏；把日志级别调到 DEBUG 就能看到 `飞牛同步明细：…` 那一行。

插件页会显示「距上次同步已 N 小时」。如果这个数字一直变大、不再自动运行，在本页点一次「保存」即可重新注册定时服务（升级插件或改动开关后偶发，定时任务被移除时不会自己回来）。

## 依赖与兼容性

- MoviePilot V2，插件放在 `plugins.v2/fnvsync/`
- 依赖 `requests`（MoviePilot 环境自带）
- 调用飞牛影视原生接口，登录兼容明文与 SHA256 两种密码方式，开访问码也能用
- 飞牛影视升级如果改了接口，同步可能失效，看插件日志定位

## 文件

- `__init__.py`：插件壳，配置表单、定时服务、详情页、状态持久化
- `fnvsync_core.py`：核心逻辑，飞牛客户端、影片匹配、同步引擎，可独立测试

## 安全说明

- 密码框是掩码输入。不想明文落库时，把密码填成 `${环境变量名}`，例如 `${FNV_PASS_A}`，再在 MoviePilot 容器里设置该变量即可。
- HTTPS 证书指纹首次连接时记录，之后每轮比对。指纹变了会直接拦住同步并在日志里说明——可能只是换了自签证书，也可能有人在中间冒充。确认是正常换证后，在插件页勾一次「重新信任证书」并保存。
- `/export` 导出的配置**不含密码**，可以安全存档；`/import` 导入时也不会覆盖密码。
- 日志里的统计行不包含地址、账号、密码。
